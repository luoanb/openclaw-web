# Requirements / 需求文档: quick-notes zentao git worklog

## Restated Understanding / 需求复述

- 我理解当前需求是：在 `quick-notes-dayu` 中新增一个【禅道打卡】Tab，用于把本地多个 Git 仓库在某一天的提交记录整理后，在禅道指定项目/迭代下创建任务并立即完成。
- 当前核心目标是：用户可以配置多个本地 Git 仓库和 WSL 子系统内的 Git 仓库，以及禅道 API 信息，默认抓取当天提交，也可以选择指定日期；系统支持手动触发和定时自动触发。
- 当前边界是：先定义本地 Git 提交抓取、提交记录预览/提交、禅道参数配置、任务记录字段映射和定时触发需求。
- 暂不处理：具体技术实现、禅道 API 适配代码、后台调度方案、数据加密方案、跨设备同步、团队多人审批流。

## Scope / 范围

- In:
  - 新增一个面向“Git 提交记录 -> 禅道创建并完成任务”的【禅道打卡】Tab。
  - 支持配置多个本地 Git 仓库路径。
  - 支持配置 WSL 子系统内的 Git 仓库。
  - 支持选择抓取日期，默认使用当天。
  - 支持从每个已配置仓库抓取该日期的提交记录。
  - 支持配置禅道 API 地址及必要调用参数。
  - 支持在禅道指定迭代下创建任务并完成任务。
  - 支持从禅道拉取项目与迭代候选项。
  - 支持项目、迭代、任务类型、预计工时、任务名模板等字段。
  - 支持手动触发同步。
  - 支持定时自动触发同步。
  - 支持展示同步结果，包括成功、失败、跳过和错误原因。
- Out:
  - 不要求第一版支持远程 Git 托管平台 API。
  - 不要求第一版自动推断禅道账号或任务归属。
  - 不要求第一版支持多人共享配置。
  - 不要求第一版修改现有任务、速记、废弃、置顶等 Tab 的既有交互。
  - 不要求第一版生成日报、周报或独立统计报表。

## User Interaction / 用户交互

- 触发入口：
  - 应用顶部新增一个 Tab，名称固定为“禅道打卡”。
- 用户操作路径：
  - 用户进入新 Tab。
  - 用户维护 Git 仓库配置，可新增、编辑、删除、启用或停用多个本地仓库。
  - 用户维护 WSL 仓库配置时，应能表达所属发行版和仓库路径，或使用系统可访问的 WSL 路径。
  - 用户维护禅道 API 配置，包括 API 地址和调用所需认证/参数，并可显式保存，避免每次打开应用重复输入。
  - 用户选择同步日期；未选择时默认当天。
  - 用户从禅道拉取并选择项目、迭代，再配置任务类型、预计工时、任务名模板等创建任务字段。
  - 用户点击手动触发后，系统抓取指定日期提交记录，生成待提交记录预览。
  - 用户确认后，系统调用禅道 API 在所选迭代下创建任务，并立即调用完成任务接口完成该任务。
  - 用户可启用定时自动触发，并设置触发时间或触发频率。
- 系统反馈：
  - 抓取阶段展示每个仓库的抓取状态、提交数量和异常原因。
  - 提交阶段展示每条记录的提交状态、禅道返回结果和失败原因。
  - 定时触发后应保留最近一次运行结果，便于用户判断是否成功。
- 状态变化：
  - 仓库配置可处于启用或停用状态。
  - 禅道配置可处于未配置、待验证、验证成功、验证失败状态。
  - 同步任务可处于未运行、抓取中、待确认、创建中、完成中、成功、部分失败、失败状态。
  - 定时任务可处于未启用、已启用、运行中、最近运行失败状态。
- 异常/边界交互：
  - 本地仓库路径不存在、不是 Git 仓库、无法读取时，应阻止该仓库参与同步并给出原因。
  - WSL 发行版不存在、WSL 不可用、仓库路径不可达、Git 命令不可用时，应阻止该仓库参与同步并给出原因。
  - 指定日期没有提交时，应展示空结果，不应误报失败。
  - 禅道 API 地址或认证失败时，应明确提示配置问题。
  - 部分仓库失败不应阻塞其他仓库的抓取结果展示。
  - 自动触发失败时，不应静默吞掉错误，应在新 Tab 中可见。
- 不应发生的交互：
  - 不应在用户未确认或未启用自动触发时向禅道创建任务。
  - 不应把本地仓库路径、禅道地址或认证信息混入现有任务/速记内容。
  - 不应因该 Tab 失败影响现有 Quick Notes 的任务和速记保存。

## Data And Mapping / 数据与映射

- Git 仓库配置：
  - 仓库名称。
  - 本地路径。
  - 仓库运行环境：Windows 本地仓库或 WSL 仓库。
  - WSL 仓库可选字段：发行版名称、Linux 路径、`\\wsl$` 路径。
  - 启用状态。
  - 可选：默认分支、作者过滤、提交消息过滤。
- 禅道配置：
  - API 地址。
  - 认证信息或访问凭据。
  - 默认项目、默认迭代、任务类型。
  - 可选指派账号；用于禅道创建任务接口的 `assignedTo` 字段，未填写时默认使用当前登录账号。
- 同步参数：
  - 日期，默认当天。
  - 项目，从禅道拉取候选后选择。
  - 迭代，从禅道拉取候选后选择。
  - 任务类型，从禅道任务类型下拉枚举中选择，例如开发。
  - 预计工时，单位为小时。
  - 任务名模板，用于根据提交记录生成禅道任务名称。
  - 完成备注模板，用于创建后完成任务时记录说明，默认复用提交明细。
- 配置保存：
  - Git 仓库配置、WSL 仓库配置、禅道连接配置、默认项目/迭代、任务类型、预计工时、任务名模板和定时配置都应保存到本地配置文件。
  - 同步日期属于本次操作参数，默认当天，不要求第一版作为长期配置保存。
- 提交记录来源字段：
  - 仓库名称。
  - commit hash。
  - commit message。
  - author。
  - commit time。
  - 可选：分支或 refs 信息。

## Acceptance Criteria / 验收标准

- [ ] 用户可以在新 Tab 中维护多个本地 Git 仓库配置，并单独启用或停用。
- [ ] 用户可以配置 WSL 子系统内的 Git 仓库，并能抓取指定日期的提交记录。
- [ ] 用户可以配置禅道 API 地址及调用所需参数，目标禅道版本为开源版 18.13。
- [ ] 用户选择某一天后，系统只抓取该日期范围内的提交记录；未选择时默认当天。
- [ ] 抓取结果按仓库展示，能看到提交数量、提交摘要和失败原因。
- [ ] 用户可以从禅道拉取项目和迭代候选，并选择任务创建目标。
- [ ] 用户可以通过下拉列表选择任务类型，并配置预计工时和任务名模板。
- [ ] 用户手动触发同步时，系统在创建禅道任务前提供可确认的待创建任务预览。
- [ ] 用户确认后，系统调用禅道 API，在所选迭代下创建任务并完成任务。
- [ ] 同步完成后，系统展示每条记录或每个仓库的成功/失败结果。
- [ ] 用户可以启用定时自动触发，并能查看最近一次自动触发的运行结果。
- [ ] 自动触发不会在配置不完整、禅道验证失败或用户未启用时创建禅道任务。
- [ ] 新 Tab 的失败状态不影响现有任务、速记、置顶、废弃、导入导出等功能。

## Constraints / 约束

- 业务约束：
  - 禅道任务的计划开始/截止日期默认与用户选择的同步日期一致。
  - 预计工时和完成任务的本次消耗单位固定为小时。
  - 项目和迭代必须从禅道候选中选择；任务类型必须从固定下拉枚举选择，默认 `devel`。
  - 定时自动触发必须由用户显式开启。
- 技术约束：
  - 本需求的技术方案阶段需先核对 `quick-notes-dayu` 当前 Tab、配置存储、Tauri 命令和本地文件访问能力。
  - 本地 Git 仓库读取与禅道 API 调用都涉及外部依赖，技术方案阶段必须明确错误处理和验证命令。
  - WSL 仓库支持是第一版范围；技术方案阶段必须明确使用 `\\wsl$` 路径访问、`wsl.exe` 内执行 Git，或两者组合的判定规则。
  - 涉及凭据时，技术方案阶段必须明确存储位置、脱敏展示和日志策略。
- 时间/兼容性约束：
  - 第一版优先服务本地单机使用。
  - 不破坏现有 Quick Notes 数据结构与既有 Tab 行为。

## Open Questions / 开放问题

- [x] Q1 禅道 API 的具体版本、认证方式和目标接口是什么？
  - 已确认：当前系统为禅道开源版 18.13。第一版按禅道 REST API v1 设计，使用 `POST /api.php/v1/tokens` 获取 Token，通过 Header `Token` 调用 `POST /api.php/v1/executions/:executionID/tasks` 在所选迭代下创建任务，再调用 `POST /api.php/v1/tasks/:id/finish` 完成任务。
- [x] Q2 一条 Git commit 应对应一条禅道任务，还是同一天多个 commit 聚合为一条任务？
  - 已确认：每次打卡/同步固定创建任务；不拉取已有任务。第一版默认把选中提交聚合为一次待创建任务，任务名称由模板生成，提交明细写入任务描述。
- [ ] Q3 任务名模板需要支持哪些变量？候选变量包括仓库名、commit message、commit hash、作者、日期。
- [ ] Q4 工时是全局固定值、按仓库配置、按 commit 平均分配，还是提交前手动编辑？
- [ ] Q5 重复提交如何判断和处理？例如同一天同一个 commit 已创建过禅道任务时，是跳过、重新创建还是提示用户选择？
- [ ] Q6 定时自动触发的触发规则是什么？例如每天固定时间、应用启动后补跑、间隔执行，或仅当应用运行时触发。
- [ ] Q7 Git 提交抓取是否需要按作者过滤？如果需要，作者标识来自 Git author、email，还是用户配置？
- [ ] Q8 是否需要支持只抓取某些分支，或默认读取当前分支全部可见提交？
- [x] Q9 禅道项目、迭代、任务类型是否需要从 API 拉取候选项，还是第一版允许用户手动填写 ID/名称？
  - 已确认：项目、迭代需要从禅道拉取候选项；任务不拉取，采用创建任务模式。
- [x] Q10 WSL 仓库配置的用户输入形式优先支持哪一种：选择发行版 + Linux 路径，直接填写 `\\wsl$\<distro>\...` 路径，还是两者都支持？
  - 已确认：第一版以“发行版 + Linux 路径”为主输入；允许用户填写 `\\wsl$\<distro>\...` 作为兼容输入，但执行 Git 时优先转换为 `wsl.exe -d <distro> -- git -C <linuxPath> ...`。
